# Sonic 애니메이션 뷰어 개발 PRD

## 1. 목표와 산출물

`pico2d`로 소닉 스프라이트 시트의 모든 동작 애니메이션을 자동 재생하는 뷰어를 만든다. **1200×800 픽셀** 창에서 각 동작을 5회 재생하고 1초 쉰 뒤 다음 동작으로 넘어간다. 모든 동작을 마치면 처음부터 무한 반복한다.

| 항목      | 내용                                               |
| --------- | -------------------------------------------------- |
| 실행 코드 | `Labs/LEC09/sonic_animation_viewer.py` 단일 파일 |
| 이미지    | 같은 폴더의 기존 `sonic-sprite.png`              |
| 조작      | 실행하면 자동 재생, 창 닫기로 종료                 |

## 2. 애니메이션 데이터

- 시트를 확인해 **동작 목록과 각 동작의 프레임 순서**를 먼저 확정한다. 행 단위로 단순 분리하지 말고, 연속된 자세가 이루는 동작을 기준으로 묶는다.
- 소닉의 동작 그림은 빠짐없이 포함한다. 제목·크레딧·장식 등은 제외한다. 한 장짜리 자세의 포함 여부는 확인 후 소스 코드 주석에 근거를 남긴다.
- 각 프레임의 이미지 좌표와 크기 `(x, y, 너비, 높이)`를 정의한다. 캐릭터가 잘리거나 옆 그림이 섞이지 않아야 하며, 이미지와 `pico2d`의 좌표계 차이를 반영한다.
- 동작 이름, 프레임 순서, 재생 속도를 데이터로 모아 관리한다. 동작을 추가하거나 프레임을 고칠 때 재생 제어 로직을 수정하지 않도록 한다.

## 3. 재생 규칙

| 단계 | 동작                                                                         |
| ---- | ---------------------------------------------------------------------------- |
| 시작 | 첫 동작의 첫 프레임부터 자동 재생한다.                                       |
| 1회  | 한 동작의 모든 프레임을 정해진 순서로 보여준다.                              |
| 반복 | 같은 동작을 정확히 5회 연속 재생한다.                                        |
| 휴식 | 5회째 마지막 프레임을 유지한 채 1초 기다린다.                                |
| 전환 | 다음 동작의 첫 프레임으로 이동한다. 마지막 동작 뒤에는 첫 동작으로 돌아간다. |

프레임 전환과 휴식은 **경과 시간**으로 계산한다. 컴퓨터 성능에 따라 재생 속도가 달라지지 않도록 하며, 기본 속도는 필요할 때 동작별로 조정할 수 있게 한다.

## 4. 화면과 실행

- 창 크기는 **1200×800 픽셀**로 고정한다. 소닉을 중앙 부근에 배치하고, 프레임 크기가 달라도 기준 위치가 크게 흔들리지 않게 한다.
- 원본 비율을 유지하면서 자세가 잘 보이도록 확대한다. 가장 큰 프레임도 화면 밖으로 잘리지 않게 한다.
- 투명 배경을 유지한다. 이미지 경로는 스크립트 위치를 기준으로 정하고, 이미지가 없으면 원인을 알 수 있게 표시한다.
- 창 닫기 이벤트를 처리해 프로그램을 정상 종료한다.

## 5. 구현 구조

단일 파일 안에서 **동작·프레임 데이터**, **현재 동작·프레임·반복 횟수·휴식 상태**, **시간 갱신**, **그리기**, **이벤트 처리**를 구분한다. 상태는 `재생 → 5회 완료 → 1초 휴식 → 다음 동작` 순으로 전환하며, 이미지는 시작할 때 한 번만 읽는다.

## 6. 완료 기준

- 시트에서 식별한 소닉의 모든 동작 애니메이션이 빠짐없이 재생된다. 프레임 순서와 잘라낸 영역을 시트와 대조한다.
- 각 동작의 5회 반복, 1초 휴식, 다음 동작 전환, 마지막 동작 이후 첫 동작 복귀를 직접 확인한다.
- 1200×800 화면에서 확대된 캐릭터가 잘리지 않고, 인접 그림이나 제목·크레딧이 보이지 않는다.
- `Labs/LEC09` 안에서 실행할 때와 다른 폴더에서 스크립트 경로를 지정해 실행할 때 모두 이미지를 찾는다.

## 7. 단계별 개발과 커밋

아래 **22단계**를 순서대로 진행한다. 각 단계에서 결과를 확인한 뒤 커밋하며, 완료 시점까지 **최소 20개의 의미 있는 커밋**을 남긴다. **커밋 메시지는 반드시 한글로 작성한다.** 스프라이트 시트 분석 결과에 따라 동작을 추가하는 단계의 수는 조정할 수 있다.

1. 단일 실행 파일을 만들고 진입점을 구성한다.
2. `pico2d`로 1200×800 창을 연다.
3. 창 닫기 이벤트를 처리해 실행을 끝낸다.
4. 종료 시 `pico2d` 자원을 정리한다.
5. 스크립트 위치를 기준으로 이미지 경로를 만든다.
6. 이미지가 없을 때 원인을 알 수 있는 오류를 표시한다.
7. 이미지를 시작할 때 한 번만 읽는다.
8. 시트의 동작 목록과 프레임 순서를 소스 코드에 기록한다.
9. 첫 동작의 프레임 좌표·크기를 정의한다.
10. 첫 프레임을 잘라 화면에 표시하고 좌표를 확인한다.
11. 원본 비율을 유지하며 1200×800 화면에 맞게 확대한다.
12. 프레임별 기준 위치를 맞춰 화면 흔들림을 줄인다.
13. 경과 시간을 읽고 프레임 전환 간격을 계산한다.
14. 첫 동작의 프레임을 순서대로 재생한다.
15. 다른 동작의 프레임 데이터를 추가하고 잘라낸 영역을 확인한다.
16. 모든 동작을 공통 데이터 형식으로 관리하고 순서를 확정한다.
17. 현재 동작·프레임·반복 횟수를 추적한다.
18. 한 동작의 마지막 프레임 뒤 첫 프레임으로 돌아가 5회 재생한다.
19. 5회째 마지막 프레임에서 재생 상태를 휴식 상태로 바꾼다.
20. 마지막 프레임을 유지하며 경과 시간으로 1초를 기다린다.
21. 다음 동작으로 전환하고, 마지막 동작 뒤에는 첫 동작으로 돌아간다.
22. 전체 동작을 재생해 누락·잘림·반복 횟수·휴식 시간을 확인하고 수정한다.

단계별 커밋에는 해당 단계에서 실제로 확인한 변경을 담는다. 동작이 많은 경우 15단계를 동작별 커밋으로 더 나눌 수 있다.
